description: Turn an accepted intent into a spec, applying the project skills
argument-hint: <intent number, e.g. 0001>
---

Read `intents/$ARGUMENTS-*.md`. It must have `Status: accepted`. If it doesn't, stop and say so.
Also read `docs/product.md` and any ADR in `docs/adr/` that the intent touches.

Write `specs/$ARGUMENTS-<same-slug>.md` with this structure:
- Header: source intent link, "Generated by: /spec-from-intent", skills applied, Reviewed by, Status: draft
- **Behaviour**: what the feature does, precisely enough to test
- **Parameters**: a table of names, defaults and where they live (`medgraph/config.py`)
- **Contract changes**: nodes, relationships, model fields (from `data-contracts`)
- **Acceptance criteria**: AC-1, AC-2, … Each must be testable by a `test_ac<N>_…` test or a single
  command.
- **Constraints**: cite the skill each one comes from
- **⚠ Flagged for the product owner**: open questions, licensing, new external services
- **Not in this spec**

Apply the `data-contracts`, `clinical-data-licensing` and `eval-hygiene` skills. Anything you are
unsure about goes under "⚠ Flagged" as a question, never as an assumption.

Do not write code. Finish by listing the flagged items for Paco.
