# ADR 0001: Neo4j as the single store for graph and vectors

- Status: accepted
- Date: 2026-11-23

## Context
We need an ontology hierarchy (IS-A traversal), patient facts and guideline chunks with embeddings,
all queryable in one retrieval step. The POC has a budget of about one week.

## Decision
Use **Neo4j 5** (Docker, with APOC) for nodes, relationships and the native vector index on
`Chunk.embedding`. Use the official `neo4j` driver, and `neo4j-graphrag` where it saves time
(vector retriever, optional Text2Cypher).

## Alternatives
- **Postgres + pgvector + recursive CTEs:** workable, but hierarchy queries are clumsy and the "graph"
  story is weaker.
- **A separate vector DB (Chroma/Qdrant) + Neo4j:** two stores, so more glue code and no hybrid
  queries.
- **RDF / GraphDB with SNOMED OWL:** semantically richer, but slower to build within a week.

## Consequences
One `docker compose up`. Cypher variable-length paths (`[:IS_A*0..]`) answer subsumption. The vector
baseline uses the same DB, so the comparison is fair.
